N 1 - Sécurité (Injection SQL) - Ligne 5 - La concaténation directe de variables dans la requête SQL permet à un attaquant d'exécuter des commandes malveillantes via le paramètre sku. - Utiliser des requêtes paramétrées avec des points d'interrogation (?) pour séparer les données du code SQL.
N 2 - Gestion des Ressources - Ligne 4 à 7 - La connexion est ouverte mais peut rester bloquée si une erreur survient avant conn.close(). De plus, commit() n'est jamais appelé, donc les changements ne sont pas persistés. - Utiliser un bloc with sqlite3.connect(...) pour garantir la fermeture et ajouter conn.commit() après l'exécution.
N 3 - Logique / Bug de duplication - Ligne 14 à 15 - La ligne alerts.append(products[i]) est répétée deux fois. Cela pollue les résultats avec des doublons inutiles au lieu de gérer une réelle priorité. - Supprimer la ligne en double. Si une priorité est nécessaire, elle doit être gérée par le tri sorted() déjà présent.
N 4 - Performance / Complexité - Ligne 12 - L'utilisation de range(len(products)) pour itérer sur une liste est une pratique non-pythonique et moins performante. - Utiliser une itération directe : for product in products:.
